# Курс «NLP, большие языковые модели и AI-агенты»

Трёхчасовое обучение для директоров операционного центра. Аудитория — руководители
без математического и ML-бэкграунда. Цель не «рассказать про AI», а довести до состояния,
в котором человек после сессии реально работает с агентом.

| Часть | Слайдов | Хронометраж | О чём |
|---|---|---|---|
| [1. Как машину научили читать](decks/01-nlp-osnovy.md) | 69 | 53:30 | Язык и неоднозначность, три эпохи NLP, откуда взялись токены, векторы смысла, классификация, языковая модель |
| [2. Большие модели и агенты](decks/02-llm-i-agenty.md) | 66 | 52:00 | Внимание и трансформер без матана, масштаб и эмерджентность, четыре стадии обучения, пять свойств моделей, RAG и инструменты, агенты |
| [3. Воркшоп](decks/03-workshop.md) | 53 | 60:25 | Команды ставят агента, подключают и пишут скиллы, решают боевую задачу |

Сквозная линия всех трёх часов: **машина не понимает текст — она предсказывает следующий
кусочек; всё остальное надстройки над этим одним трюком.** Часть 1 объясняет трюк, часть 2 —
что случилось, когда его отмасштабировали, часть 3 — как этим пользоваться руками.

## Сборка

```bash
npm install
make doctor      # проверить, что нашёлся Chromium и marp
make all         # PDF + HTML + спикерские сценарии
make check       # число слайдов, переполнения, перегруз текстом
make handouts    # печатные раздатки воркшопа в A4
make release     # готовые PDF + PPTX + HTML в release/ (коммитятся)
```

Результат в `build/` (в git не попадает). Отдельная колода: `make build/01-nlp-osnovy.pdf`.
Правка с живым просмотром: `make watch DECK=01-nlp-osnovy`.

### Что важно знать про сборку

Экспорт в PDF идёт через Chromium, у которого **нет выхода в сеть**. Поэтому в
`marp.config.mjs` принудительно выключены эмодзи и формулы: marp-core рендерит их через
`cdn.jsdelivr.net`, и в PDF получились бы битые картинки. По той же причине в теме нет
веб-шрифтов — только системный стек, который везде покрывает кириллицу.

`CHROME_PATH` обязателен, Makefile находит его сам: локальный Chromium здесь, Google Chrome
на macOS.

## Структура

```
decks/       три колоды, каждая — один плоский .md
theme/       corporate.css (16:9) и handout.css (A4) + шпаргалка по классам
workshop/    печатные раздатки и три готовых скилла
scripts/     проверка колод, сверка страниц PDF, сборка сценария, инлайн картинок
assets/      картинки колод: top-memes/ (шаблоны), workshop/ (найденное поиском)
assets/memes/      каталоги «слайд → картинка», оценка (OTSENKA.md), fetch.sh
release/     готовые PDF + PPTX + HTML — пересобираются `make release`
original_course/   исходные лекции ВШЭ — архив только для чтения
```

Каждый слайд начинается с якоря `<!-- @ 3.4 токены: разбор фразы -->` — по нему удобно
искать в файле на 1000+ строк. Спикерские заметки лежат в HTML-комментариях, строка
`Хронометраж: N` собирается в сводку по времени.

Как пользоваться классами слайдов и компонентами диаграмм — в [theme/README.md](theme/README.md).

## Спикерские заметки

Три способа, все собираются одной командой:

1. **Presenter view** — открыть `build/*.html`, нажать `P`. Заметки и таймер во втором окне.
   Основной инструмент в зале.
2. **PDF с аннотациями** — `--pdf-notes` уже включён. Запасной вариант.
3. **Печатный сценарий** — `build/notes-*.md`: номер слайда, заголовок, тезисы, хронометраж,
   в шапке — сумма времени. Единственный способ заранее увидеть, влезает ли час.

## Воркшоп

Основной путь установки — **Hermes Desktop**: графический установщик под macOS и Windows,
который сам ставит Python, Node, ripgrep и ffmpeg. Единственный внешний пререквизит — Git.
Запасной путь — **OpenClaw** через `npm`, для одной команды рядом с техническим помощником;
он же даёт каналы Telegram/WhatsApp, на которых построен план Б.

| Файл | Что | Кому |
|---|---|---|
| `00-preflight-organizer.md` | Чек-лист подготовки за неделю / три дня / день | организатору |
| `10-install-macos.md`, `11-install-windows.md` | Установка, один шаг на страницу | командам, печатать |

## Правила репозитория

- Готовые сборки живут в `release/` (PDF + PPTX + HTML, пересобрать: `make release`).
  Это осознанное исключение из правила «бинарники не коммитим»: файлы нужны
  прямо в репозитории. `build/` по-прежнему в git не попадает. HTML в `release/`
  самодостаточен — картинки встроены base64, файл можно отправить одним вложением.
  PPTX — послайдовые картинки (точный рендер), а не редактируемые фигуры.
- `original_course/` — архив только для чтения. Диаграммы оттуда не переиспользуем:
  большая их часть — скриншоты чужих курсов (Stanford CS224n, курс Лены Войты).
  Все схемы в колодах нарисованы заново на CSS и SVG.
- Новые бинарники допустимы только как скриншоты воркшопа: PNG, ширина до 1600, до 300 КБ.
